DSH-NetShell 把本机 Shell 和远程 SSH 终端带进 DeepSeek Harness。你可以在 DSH 界面里管理服务器、查看实时输出，也可以让 AI 通过受控工具执行命令；危险操作会先暂停，等你确认后才会继续。

## 为什么开发

AI 能帮你操作服务器，但真正可用的终端还需要三件事：

- **看得见**: 人工输入和 AI 执行都在同一个终端面板里实时显示。
- **拦得住**: 删除、重启、删库、强推等高风险命令会被拦下。
- **密码不出会话**: SSH 密码只保存到 DSH 加密凭据库，不进入 AI 消息、工具返回或日志。

## 安装

已发布包：

```bash
dsh plugin --profile web add @xgone/dsh-netshell
```

从本地源码安装：

```bash
dsh plugin --profile web add link:/path/to/dsh-netshell
```

安装后重启 DSH Web。打开 **设置 → 终端**，看到插件配置区即表示加载成功。

## 使用方法

### 1. 先试本地终端

打开主区域的 **终端** Tab，在左侧 **本地终端** 行点击 **新建**。插件会按当前系统选择可用的 `bash`、`sh`、PowerShell 或 `cmd`，不会读取远程服务器档案和 SSH 密码。

### 2. 添加远程服务器

打开 **设置 → 终端 → 新增**，填写：

1. 名称、主机、端口和用户名；
2. 认证方式：密码、私钥或 `ssh-agent`；
3. 权限等级，第一次使用建议保持默认的 `guarded`；
4. 可选的服务器规则。

密码保存后只显示“已设置”，不会再次回显密码。回到 **终端** Tab，在服务器行点击 **连接** 即可打开 SSH 会话。

### 3. 处理危险命令

命令在回车提交时检查。规则分为三种动作：

| 动作 | 结果 |
| --- | --- |
| `allow` | 直接执行 |
| `ask` | 暂停并等待你的确认 |
| `deny` | 直接拦截，不会执行 |

权限等级：

| 等级 | 适用场景 |
| --- | --- |
| `open` | 日常使用；只保留硬拦截规则 |
| `guarded`（默认） | 常规服务器；危险命令需要确认 |
| `locked` | 敏感服务器；只有明确允许的命令可以直接执行 |

遇到 `ask` 命令时，你可以选择 **执行一次**、**永久放行该命令** 或 **拒绝**。永久放行只对当前服务器和当前命令文本生效。

### 4. 查看历史和状态

终端底栏会显示执行、拦截和放行次数。点击 **历史** 可以查看本会话的命令和裁决记录。切换到其他 DSH Tab 不会主动断开后台会话。

## AI 使用

插件提供两个模型工具：

| 工具 | 用途 |
| --- | --- |
| `netshell_servers` | 列出服务器档案，不返回密码 |
| `netshell_run` | 在指定服务器上执行一条命令 |

AI 和人工输入共用同一套 Guard。`deny` 命令不会执行，`ask` 命令必须由你在 DSH 的确认卡或终端面板中裁决。AI 看不到密码，也不能伪造确认结果。

## 安全边界

这是命令操作护栏，不是完整的安全沙箱。它只保护通过本插件终端和 `netshell_run` 进入的命令；其他插件或通用 Shell 工具建立的 SSH 连接不在拦截范围内。对敏感环境建议使用 `locked`，并避免在交互式程序内部执行未审查的操作。

SSH 主机指纹保存在插件私有的 `~/.dsh/netshell/known_hosts`，不会写入用户手工 SSH 使用的 `~/.ssh/known_hosts`。

## 常见问题

**连接失败怎么办？** 检查主机、端口、用户名和认证方式。若提示主机指纹发生变化，确认服务器确已重装后，再按提示清理插件私有 `known_hosts` 记录。

**密码会被 AI 看到吗？** 不会。密码由 Host 侧从 DSH 加密凭据库读取，只用于建立 SSH 连接；列表、工具返回、日志和终端输出都不包含密码值。
