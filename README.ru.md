<p align="center"><strong>Защищённый локальный и удалённый SSH-терминал для DeepSeek Harness</strong></p>

DSH-NetShell позволяет управлять серверами и работать в живом терминале внутри DSH, оставляя человеку понятную точку подтверждения перед выполнением опасных команд. Ручной ввод и действия ИИ проходят через один и тот же страж команд. Язык интерфейса следует локали DSH: китайский, английский, русский, японский, немецкий, французский, испанский или корейский.

## Возможности

| Возможность | Что вы получаете |
| --- | --- |
| Локальный терминал | Запуск `bash`, `sh`, PowerShell или `cmd` на текущей машине без настройки SSH; в Windows приоритет у PowerShell/pwsh/cmd |
| Удалённый SSH | Управление хостами, портами, пользователями и способом аутентификации, несколько сессий одновременно; поддерживается Windows OpenSSH Client |
| Страж команд | `allow` — выполняется сразу, `ask` — ждёт подтверждения, `deny` — блокируется |
| Видимое выполнение | Ручной ввод и команды ИИ отображаются в одной живой панели терминала |
| Изоляция учётных данных | Пароли SSH попадают только в зашифрованное хранилище DSH и не появляются в сообщениях ИИ, результатах инструментов и журналах |
| История команд | Счётчики выполненных, заблокированных и разрешённых команд плюс запись по каждому решению |
| Язык интерфейса | Китайский, английский, русский, японский, немецкий, французский, испанский или корейский — вслед за локалью DSH |

## Установка

Опубликованный пакет:

```bash
dsh plugin --profile web add @xgone/dsh-netshell
```

Из локальной копии исходников:

```bash
dsh plugin --profile web add link:/path/to/dsh-netshell
```

В Windows нужен установленный Windows OpenSSH Client (проверка — `ssh -V`); для автоматической подстановки пароля требуется поддержка `SSH_ASKPASS_REQUIRE=force` (рекомендуется версия 8.7+). После установки перезапустите DSH Web и откройте **Настройки → Терминал**.

## Быстрый старт

### Локальный терминал

1. Откройте вкладку **Терминал** в основной области.
2. На строке **Локальный терминал** нажмите **Создать**.
3. Вводите команды и следите за выводом в реальном времени.

Локальный терминал не читает профили удалённых серверов и пароли SSH.

### Удалённый сервер

1. Откройте **Настройки → Терминал**: раздел **Серверы** и кнопка **+ Создать** — это форма **Новый сервер**.
2. Укажите **Название**, **Хост**, **Порт** и **Пользователь**.
3. Выберите **Аутентификацию**: **Пароль**, **Ключ** или **ssh-agent**.
4. Выберите **Уровень доступа**; для первого подключения лучше оставить `guarded`.
5. Вернитесь на вкладку **Терминал** и нажмите **Подключиться** на строке сервера.

Сохранённый пароль отображается только как «Пароль сохранён в учётных данных» и больше никогда не выводится. В Windows аутентификация по ключу использует временную копию, защищённую ACL текущего пользователя; после сессии копия удаляется, а исходный файл ключа (в том числе в OneDrive) и его ACL не меняются.

### Опасные команды

Команды проверяются в момент отправки по Enter:

| Уровень | Поведение |
| --- | --- |
| `open` («свободный») | Повседневная работа; действуют только жёсткие правила блокировки |
| `guarded` («по умолчанию») | Опасные команды останавливаются и ждут подтверждения |
| `locked` («строгий») | Напрямую выполняются только явно разрешённые команды |

Для команды с решением `ask` выберите **Выполнить один раз**, **Всегда разрешать эту команду** или **Отклонить**. Постоянное разрешение действует только для текущего сервера и точного текста команды.

## Инструменты для ИИ

Плагин предоставляет два инструмента модели:

| Инструмент | Назначение |
| --- | --- |
| `netshell_servers` | Показывает профили серверов без паролей |
| `netshell_run` | Выполняет одну команду на выбранном сервере |

Команды ИИ и ручной ввод проходят через один и тот же Guard. Команды с решением `deny` не выполняются, а для `ask` нужно ваше решение в карточке подтверждения DSH или в панели терминала; ИИ не видит пароли и не может подделать результат подтверждения.

При первом обращении сессии модели к серверу, а также после того как вы вручную отключили этот сервер, `netshell_run` сначала запрашивает подтверждение удалённого подключения и только затем запускает SSH. Подтверждение хранится отдельно для каждой пары «сессия модели — сервер» в пределах жизни плагина: разные сессии модели подтверждают независимо, даже если переиспользуют одну SSH-сессию. Сетевой сбой, аварийное завершение SSH или таймаут подключения запускают переподключение только для уже подтверждённой сессии модели и не приводят к повторному вопросу. Уже открытая вручную сессия в интерфейсе не заменяет подтверждение для модели; если служба подтверждений недоступна, плагин отказывается подключаться автоматически.

## Границы безопасности

Это страж команд, а не полноценная песочница. Он защищает только команды, приходящие через терминал плагина и `netshell_run`; SSH-соединения, установленные другими плагинами или обычными shell-инструментами, вне его области действия. Для чувствительных сред используйте `locked` и отдельно проверяйте действия внутри интерактивных программ.

Отпечатки SSH-хостов хранятся в приватном для плагина файле `$DSH_HOME/netshell/known_hosts` (если `DSH_HOME` не задан — `~/.dsh/netshell`) и не попадают в пользовательский `~/.ssh/known_hosts`.

## Частые вопросы

**Что проверить, если подключение не удаётся?** Проверьте хост, порт, имя пользователя и способ аутентификации. Если сообщается об изменении отпечатка хоста, убедитесь, что сервер действительно переустановлен, и только потом удалите устаревшую запись из приватного `known_hosts` плагина.

**Может ли ИИ увидеть мой пароль?** Нет. Хост-часть читает пароль из зашифрованного хранилища DSH только на время установления SSH-соединения; списки профилей, результаты инструментов, журналы и вывод терминала не содержат значения пароля.
